# Project Governance

## Overview
This document outlines the governance model for **[Project Name]**. The project operates as an open-source initiative managed by its core maintainers and contributors.

## Roles & Responsibilities

### 1. Contributors
* **Who they are:** Anyone who contributes code, documentation, bug reports, or feedback to the project.
* **Responsibilities:** Follow the [Code of Conduct](CODE_OF_CONDUCT.md), test changes, and participate constructively in community discussions.

### 2. Maintainers
* **Who they are:** Trusted community members responsible for the technical direction and day-to-day oversight of the project (initially managed by @gutiluis).
* **Responsibilities:**
  * Reviewing and merging pull requests.
  * Managing issue queues and project milestones.
  * Enforcing the Code of Conduct and community guidelines.
  * Having commit and push access to core branches.

## Decision-Making Process
* **Routine Changes:** Bug fixes, documentation updates, and minor feature additions can be approved and merged by a single maintainer.
* **Major Changes:** Significant architectural updates, breaking API changes, or modifications to project governance require consensus among the core maintainers. 
* **Dispute Resolution:** If maintainers disagree, the final technical decision rests with the primary project lead (@gutiluis).

## Changes to Governance
Modifications to this governance structure can be proposed by opening a pull request or an issue for community discussion.
